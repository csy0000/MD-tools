## System: build once with Amber

The solute is neutral blocked alanine dipeptide: `ACE–ALA–NME`.

Use tleap with:

- protein force field: ff19SB;
- water: OPC;
- periodic truncated-octahedral solvent box;
- minimum 12.0 Å padding from solute to box boundary;
- no counterions unless tleap reports a nonzero solute charge, in which case stop and diagnose the build rather than adding ions automatically.

Verify the exact Amber26 leaprc names and OPC box unit from the installed distribution. Save:

- `tleap.in`;
- captured `tleap.stdout` and `leap.log`;
- solvated PDB;
- `alanine.prmtop`;
- `alanine.inpcrd`;
- a concise `forcefield.json`;
- SHA-256 hashes for every retained build input and output.

`forcefield.json` must record the solute identity, terminal caps, total charge, force-field/water identifiers, Amber versions, leaprc files, solvation command, box type, requested padding, realized atom/residue/water counts and box vectors, build commands, warnings, manual edits (normally none), artifact paths, and hashes. Preserve raw logs as audit evidence; the JSON is their readable index, not a replacement.

The same exact `prmtop` and `inpcrd` bytes are inputs to both engines. OpenMM must not rebuild the system from ForceField XML for the primary comparison.

## Shared protocol

Unless the installed Amber implementation forces a documented difference, use:

- temperature: 300 K;
- pressure: 1 bar;
- timestep: 2 fs;
- PME periodic electrostatics;
- 9 Å real-space nonbonded cutoff;
- constraints/SHAKE on bonds involving hydrogen;
- no hydrogen-mass repartitioning;
- Langevin collision/friction coefficient: 1 ps⁻¹;
- explicit, recorded nonzero random seeds;
- trajectory and thermodynamic reporting intervals chosen once and matched by physical time.

Stages:

| stage | length | ensemble | positional restraint |
|---|---:|---|---|
| minimization | maximum 1,000 iterations | — | all ACE–ALA–NME atoms, 1 kcal mol⁻¹ Å⁻² |
| NVT | 10 ps = 5,000 steps | 300 K | same restraint |
| NPT equilibration | 10 ps = 5,000 steps | 300 K, 1 bar | same restraint |
| production | 1 ns = 500,000 steps | 300 K, 1 bar | none |

Use the initial Amber `inpcrd` solute coordinates as the common positional-restraint reference for minimization, NVT, and NPT equilibration. Production begins from each engine's own final equilibration state.

For Amber, use current Amber26-supported Langevin and Monte Carlo barostat settings when available. For OpenMM use `LangevinMiddleIntegrator` and `MonteCarloBarostat`. Record that thermostat/barostat/minimizer algorithms are not identical across engines. Match physical parameters and barostat attempt frequency as closely as the APIs permit; never describe the trajectories as expected to be identical.

Primary correctness runs should use reproducible CPU/reference-capable paths where practical (`sander` or CPU `pmemd` for Amber; OpenMM CPU or Reference as appropriate). An optional CUDA performance run may be added only after the primary comparison passes and must be reported separately.

## Pre-dynamics equivalence gates

Do not run the full protocol until these gates pass or a scientifically understood difference is documented.

### 1. Topology and coordinates

Prove both engines read identical particle/atom counts, masses, charges, box vectors, constraints, and initial coordinates from the same files. OPC extra particles must be counted explicitly and must not be confused with topology atoms.

### 2. Unrestrained energy and forces

On identical initial coordinates, compare total potential energy and available bonded/nonbonded components. Compare per-particle forces after accounting for units and atom/particle ordering. Report absolute and relative differences and explain PME decomposition differences instead of forcing incomparable component labels together.

### 3. Restraint convention

Do not assume `restraint_wt=1.0` maps directly to an OpenMM harmonic coefficient. Construct a tiny controlled check by displacing one restrained solute atom by a known distance with all other coordinates fixed. Measure the Amber positional-restraint energy and choose the OpenMM `CustomExternalForce` expression/coefficient that reproduces it. Record whether the energy convention contains a factor of one half.

### 4. Minimization interpretation

Amber and OpenMM use different minimizers. Treat 1,000 as the maximum iteration count in each engine and compare final energy/force sanity, not step-by-step coordinates. Record Amber `ncyc` and OpenMM tolerance explicitly.
