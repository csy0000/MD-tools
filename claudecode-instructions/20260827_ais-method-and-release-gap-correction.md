1. edited explicit-solvent YAML must not silently create an unsupported protein/water pairing;
2. runtime acceptance must use the exact stable OpenMM 8.6.0 release, not a development build whose version string merely begins with 8.6.0.

## 3. AIS configuration

Add AIS to the existing canonical method list. Preserve cMD and REST2 behavior.

show-default AIS and sys-config --method AIS must write a clear editable AIS block. Use OpenMM/REST2 terminology already present in the repository. The default document must contain:

    AIS:
      path:
        type: rest2_tau
        tau_start: 0.5
        tau_end: 0.0
        interpolation: linear
        omega_exclusion: true
        enhanced_region: solute
        switching_duration_ps: null
        parameter_update_interval_steps: 1
      source:
        trajectory: null
        topology: null
        start_time_ps: null
        end_time_ps: null
        first_frame_time_ps: null
        frame_interval_ps: null
        number_of_trajectories: null
        selection: uniform_random
        allow_sampling_with_replacement: false
      output:
        number_of_observations: 21
        include_start: true
        include_end: true
        coordinates: whole_system
      execution:
        platform: CUDA
        gpu_devices: auto

The null fields are required user inputs, not silent defaults. Validation errors must name the field and explain what it means.

Scientific meaning:

- tau is the source parameter.
- s = (1 - tau)^2.
- the solute-environment scaling factor is sqrt(s) = 1 - tau.
- the default path is linear in tau from 0.5 to 0.0.
- therefore sqrt(s) is linear while s is quadratic.
- AIS uses the same enhanced-region and omega-exclusion definitions as cMD/REST2.
- temperature and beta come from common.temperature_kelvin and remain constant throughout the path.
- this is Hamiltonian switching, not temperature annealing.
- the first implementation supports a forward path. Structure the configuration so a later reverse path can be added, but do not implement a bidirectional workflow now.

Validation must require:

- tau values in the supported interval and tau_start different from tau_end;
- interpolation equal to linear for this implementation;
- positive switching_duration_ps;
- positive whole-number parameter_update_interval_steps;
- number_of_trajectories is a positive integer;
- start_time_ps and end_time_ps are present, nonnegative, and end is not earlier than start;
- exactly 21 observations by default, including both endpoints;
- the number of switching parameter updates is divisible by number_of_observations - 1, so all 21 observation points are exact and evenly spaced rather than rounded;
- whole-system output only in this first implementation.

Do not add a concept of chunks to YAML. Independent AIS trajectories are the natural execution units.

## 4. Source-trajectory contract

AIS starts from an existing equilibrium trajectory, not automatically from the common equilibration chain. Consequently AIS must not be included in MD/run_all.sh.

Use MDTraj to read whole-system DCD trajectories and their periodic box vectors. Add mdtraj to the installation environment and validation only because the advertised AIS command requires it.

The source contract is:

- trajectory is resolved relative to MD/md.config.yaml or the generated MD project, with the resolved path recorded;
- topology defaults to the prepared inputs/topology.pdb when null, but the resolved choice is recorded;
- start_time_ps and end_time_ps are inclusive;
- source frames are restricted to that time interval;
- frame times are obtained from a trustworthy companion resolved_run.yaml/provenance record when available;
- otherwise first_frame_time_ps and frame_interval_ps are required;
- never infer physical time from a frame index alone;
- never assume a DCD header provides the intended production time origin;
- validate atom count and atom order against inputs/topology.pdb;
- explicit-solvent frames must provide valid periodic box vectors;
- the source Hamiltonian tau must equal path.tau_start. Read it from companion provenance when possible; if it cannot be established, fail and ask the user to identify it explicitly in configuration rather than assuming tau=0.5;
- source selection is deterministic from the recorded master seed;
- uniform_random means sampling uniformly from eligible frames;
- sampling without replacement is the default and fails clearly if too many trajectories are requested;
- because DCD does not contain velocities, assign Maxwell-Boltzmann velocities at the common temperature using a distinct recorded seed for every AIS trajectory.

Do not concatenate independent AIS paths into a single DCD that looks like one continuous trajectory.

## 5. Exact REST2 switching implementation

Reuse the current REST2 decomposition and omega-exclusion logic. There must be one source of truth for the static REST2 scaling rules and the dynamic AIS scaling rules.

At tau:

    s = (1 - tau)^2
    sqrt_s = 1 - tau

The dynamic System must reproduce a separately constructed static REST2 System at the same tau. Test energies and forces at tau values 0.0, 0.25, and 0.5 for:

- solute-solute electrostatics;
- solute-environment electrostatics;
- solute-solute Lennard-Jones;
- solute-environment Lennard-Jones;
- scaled solute torsions;
- omega-excluded torsions;
- unscaled environment terms.

Do not implement total-energy interpolation between endpoint Systems. The Hamiltonian must actually change through force parameters using the same decomposition as REST2.

For each switching update j from tau_j to tau_j+1, use the discrete nonequilibrium convention:

    delta_W_j = U(tau_j+1, x_j) - U(tau_j, x_j)

Then propagate at tau_j+1 for parameter_update_interval_steps. Accumulate physical work in kJ/mol and reduced work beta*W. beta is the one common physical beta.

The observation convention must be explicit and tested:

- observation 0: source coordinates at tau_start, cumulative work 0;
- observations 1 through 20: coordinates after propagation to their scheduled tau value, paired with cumulative work through the parameter change that reached that tau;
- observation 20: coordinates at tau_end and the final cumulative work.

For a frozen-coordinate test, cumulative work must telescope to U(tau_end, x) - U(tau_start, x). A constant-tau diagnostic path must give zero work to numerical tolerance, even though the public forward configuration requires distinct endpoints.

The first AIS implementation must propagate at fixed volume:

- no active barostat during the switching path;
- an explicit source frame keeps its source box vectors;
- implicit solvent remains nonperiodic;
- document that an NPT source ensemble may seed fixed-box nonequilibrium paths, but pressure-volume work is not part of this first implementation.

Only run.py, run.sh, the scaling helper, and path_definition.yaml need to exist immediately after md-gen. Runtime records and trajectory directories are created by the run.

Each trajectory directory is one independent AIS switching path. observations.dcd contains exactly 21 whole-system coordinate frames by default. observations.csv contains one row per DCD frame with at least:

- ais_trajectory_index;
- observation_index;
- coordinate_frame_index;
- source_frame_index;
- source_time_ps;
- protocol_step;
- switching_time_ps;
- tau;

- cumulative_work_kj_mol;

- integrator_seed;
- velocity_seed;
- GPU device;
- DCD filename.

path_definition.yaml records the full path definition, update/observation schedule, work convention, ensemble, enhanced region, omega exclusion, and template identity.

resolved_run.yaml and provenance.yaml record:

- exact MD-templates implementation identity;
- actual OpenMM version;
- input hashes and source trajectory identity;
- resolved absolute source during execution and portable configured relative path;

- limitations: forward only, no mid-path resume, no NPT switching work, DCD has no velocities.

The generated runtime must not import md_templates.

## 7. Execution and restart scope

AIS trajectories are independent and may run concurrently.

- CUDA is the default and must not silently fall back to CPU.
- gpu_devices: auto detects visible CUDA devices.
- run at most min(number_of_trajectories, available_GPU_count) trajectories concurrently.
- assign trajectories to devices deterministically.
- trajectories sharing a GPU run sequentially.
- every trajectory has distinct deterministic integrator and velocity seeds.
- do not use one multithreaded OpenMM Context across GPUs; use isolated worker processes.

Keep restart behavior simple:

- a completely finished trajectory, validated by its observation count and completion record, is skipped;
- an incomplete trajectory is not silently treated as complete;
- do not build a complex mid-switch checkpoint/recovery system in this task;
- rerunning an incomplete path must either replace its incomplete outputs safely or require that one trajectory directory be moved aside, with the behavior documented clearly;
- never append a second path to an existing observations.dcd.
