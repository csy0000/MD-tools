Three fixes found by the hpREST2 campaign running this engine in anger. They are the same shape:
**a default that means something specific, where nothing was meant.**

### 1. `--extend-from` generated a group file its own parser rejected

`--extend-from` takes the physical state from the parent's checkpoint — positions, velocities,
box, the state-to-walker map, the RNG stream, the exchange count — so the group file it writes
correctly carries no `-c`. `_parse_group_line` required `coordinates` on every line regardless:

```
replica executor: REST2.group:7: no coordinates given
[rank 0/6] fatal: REST2 rank 0: the executor returned 2
```

Every rank aborts. This stopped an explicit-solvent ladder at 100 ns/state of the 500 it was asked
for. **Nothing exercised a generated group file against the parser that has to read it**, which is
how the two halves came to disagree.

`coordinates` is now required only when an extension is not in force, and the refusal says when it
is optional. A fresh ladder still cannot start without a starting state; the other required fields
are unchanged; and a caller who passes `-c` on an extension anyway is not refused — the value is
inert, not forbidden.

### 2. `-o`, `-log`, `-r` and `-chk` now default by segment

The trajectories, the state table and the per-force-group energies have carried a segment for some
time. These four did not: they come from the command line, whatever path is handed over is what
gets written, and `SimOut` opens its file `"w"`.

So a second in-place segment **destroyed** the first segment's human-readable output and its
provenance record, leaving a directory in which `mdout_prod2.csv` and `solute_prod2.nc` sat beside
a `cMD.log` describing only segment 2. The half of the directory this package names was safe; the
half the caller names was not, and the two look alike.

`stage_artifact_name` applies `info_csv_name`'s rule to all four, never segments a stage that runs
once per chain, and an explicitly passed path still wins — this changes the default, not the
override.

### 3. A remedy message named flags the command in hand does not define

0.5.1 fixed messages telling an `md-run` user to `pass --force` and added a test to keep them
fixed. That test had two gaps: its file list omitted `remd/executor.py`, which `md-run` dispatches
into, and its pattern captured only the first flag after "pass".

Widening both found a live instance — *"Pass `--resume` to continue that run, `--extend N` to
lengthen it, or `--force` to replace it deliberately"* — where `md-run` defines neither `--extend`
nor `--force`. The imperative now names only the flag both commands have; the others are described
and attributed to the command that has them.

### Tests

New: `tests/test_extension_group_file.py` (7), `tests/test_stage_artifact_names.py` (5). The
regression is one of them — generate the shape `--extend-from` emits, then parse it.

`test_runtime_contract_matrix.py`, `test_extension_group_file.py`, `test_stage_artifact_names.py`
and `test_resume_identity.py`: **83 passed**. Full suite running; I will post the number here.

### What this does NOT cover

The CPU tests prove the parser and the naming rule. They do not prove that a ladder still
exchanges, that an extension **joins** its parent rather than restarting, or that a harmonic
restraint identical on every rung cancels out of the acceptance criterion. Those need GPUs and are
specified in `docs/claudecode-instructions/20260913_gpu-tests-for-0.5.3.md`, with two devices
reserved. **Please do not merge to `main` before those report.**
