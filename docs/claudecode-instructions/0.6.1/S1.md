## First task, before implementing anything

Write the executable fixtures. They are the specification, and they will be wrong in interesting
ways before the implementation is:

1. A mask-grammar table: every accepted form (`":45"`, `":45,46,59"`, `":45-50"`, `":45,48-52"`)
   and every refused one (chain qualifiers, atom selectors, operators, wildcards, out of range,
   empty match), each with the message it should produce.
2. A small explicit-solvent fixture with two chains, a short peptide and two copies of one ligand
   plus one distinct ligand — enough to express: phi/psi across a residue boundary, chi1 reaching
   backbone N and C-alpha, one copy of a compound selected while its twin is not, and a CMAP pair
   split between selected and unselected.
3. The two mode tests: no new selector field reproduces 0.6.0 **exactly**, and any new selector
   field switches to explicit mode where an omitted category means none.

Then implement. Land the resolved selection record (`md-tools-solute-selection/2.0`) early, since
everything else is written in terms of it.

## What the evidence has to show

Deterministic first, in this order: analytic S–S / S–E / E–E factors per pair and per exception at
several tau; `tau = 0` identity; legacy equivalence; the boundary cases; reordered atoms; an
exclusion file mutated after the record was written; CMAP shared and mixed maps.

Only then the CUDA explicit-solvent ladders — peptide and protein–ligand, selective backbone,
selective sidechains, ligand-only, and combined — with direct exchange energies at stored
coordinates, resume identity and refusal, standalone export, and registration.

Effective-temperature intuition proves nothing. Test the energy the code computes.

A CPU run is not CUDA evidence and a skipped lane is not a pass: a stale MPS pipe directory once
made an entire 110-test GPU lane skip and exit 0. Read the counts.
