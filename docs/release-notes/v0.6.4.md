# 0.6.4 — the alchemical transformation, as far as it actually goes

This release collects the alchemical work into a shippable state and says precisely where that
state ends. The honest summary is three sentences: a topology plan is a finished artefact, a
configuration naming one resolves through `build-md` and `md-run`, and **neither surface runs a
window yet** — both refuse by name rather than produce something that looks complete. The runtime
underneath does work, is driven from Python, and has been checked against a free energy obtained a
different way.

**No existing protocol changes.** cMD, REST2, AIS and umbrella are untouched. `protocol:
alchemical` is a new value; every configuration that resolved in 0.6.3 resolves identically.

## `protocol: alchemical` resolves

`build-md` accepts an `alchemical` section:

```yaml
protocol: alchemical
alchemical:
  plan: ./plan                    # what `md-openmm combine-topology` wrote
  lambda_path: staged             # or linear
  staged_knot: 0.5
  number_of_windows: 11           # or lambda_values: 0.0, 0.25, 0.5, 0.75, 1.0
  window_steps: 500000
  equilibration_steps: 10000
  report_interval_steps: 500
  checkpoint_interval_steps: 50000
```

and `md-run` parses the matching `&alchemical` block. Every `.in` round-trips back to exactly the
`resolved.config` beside it, both ways of placing the windows included — the same contract the
other four protocols keep, and a test rather than a convention.

Nothing in the section restates a fact the plan already holds. The two end states, the atom map,
the environment and the combined numbering are in the plan, which carries its own digests and is
validated where it is LOADED. A second copy here would be the one that drifts.

**A window must sit exactly on a staged path's knot.** The slope of every λ component jumps there,
so dU/ds has different left and right values and no trapezoid drawn across the knot recovers the
integral. A count whose grid misses it is refused with the arithmetic that would fix it, never
moved to the nearest grid point.

**Value-level refusals are delegated**, not restated. `SoftcoreSettings`, `WindowSettings` and
`md_tools.alchemy.paths` enforce their own rules at run time, and the configuration layer hands the
resolved values to them. A configuration therefore cannot accept a setting the node will refuse
three stages of equilibration later, nor refuse one the runtime would have accepted.

## And both surfaces refuse to run one

`build-md` raises before writing anything, and `md-run` returns 2 before `-odir` exists.

This is deliberate and it is the interesting part. Left to fall through, `build-md` would hand back
the preparation chain alone — minimisation and equilibration, each correct in itself — and a
`run.sh` built from it would run to completion having sampled no window at all. `md-run` would
report the success of a campaign it never ran. **A generated directory is a claim about what it
runs**, and a refusal that names the gap is worth more than an approximation of the thing.

An input naming a preparation `stage` is unaffected: `stage` decides, not `protocol`, and
minimisation is minimisation.

## What the runtime has been shown to compute

New page: [alchemy/validation.md](../openmm_methods/alchemy/validation.md).

Three FreeSolv molecules decoupled from TIP3P water, twelve windows, 1 ns each, three repeats —
nine legs, 108 windows, 108 ns on CUDA/mixed:

| ligand | ΔG_hyd, kcal/mol | ± (repeat spread) | experiment |
|---|---|---|---|
| ethane | **+2.478** | 0.033 | +1.83 |
| chloroethane | **+0.839** | 0.067 | −0.63 |
| ethanol | **−3.523** | 0.025 | −5.00 |

Ethanol is in the set because its hydration is dominated by the **charging** leg, which the two
weakly polar molecules barely exercise.

The check that matters is not agreement with experiment — a force field can miss that for reasons
that are not defects. It is that ΔG_hyd(chloroethane) − ΔG_hyd(ethane) obtained by DECOUPLING each
reproduces the same difference obtained by MUTATING one into the other: a different plan, different
end states, different particles appearing.

| route | ΔΔG_hyd, kcal/mol |
|---|---|
| decoupling each ligand | **−1.639 ± 0.074** |
| mutating one into the other | **−1.743 ± 0.026** |

**0.104 ± 0.079 apart, or 1.3 σ.** Consistent.

## A number this page nearly shipped

The first repeat alone gave −1.759 against −1.743 — an agreement to **0.016**, and it was written
into the validation page as the headline before the other repeats finished.

It was a coincidence of one realisation. Chloroethane's three repeats span 0.747 to 0.969, so any
single one lands about 0.1 from the mean by luck in either direction. **An agreement much tighter
than the reproducibility of the two things being compared is not a stronger result; it is a sign
that not enough of them have been run.** The caution is kept in the page beside the corrected
number rather than quietly replaced by it.

Two related corrections in the same page: the error bar is the REPEAT SPREAD, not MBAR's σ (which
is the within-run error at fixed sampling and cannot see what differs between realisations); and an
earlier claim that the spread exceeds the within-run error came from two points and is false at
three — spread/σ is 0.4 to 1.2, comparable, neither dominant.

## The self-check record carries its sample count

`evaluation_self_check_kJ_mol` is the largest disagreement between the evaluation Context and the
sampling Context over every report a window made. As a worst-case witness that is right; as a
number to compare BETWEEN windows it is not, because it grows with how many reports there were. A
longer window looks worse for being longer, and a plot of it across a ladder measures window
length.

The completion record therefore carries `evaluation_self_check_n` and
`evaluation_self_check_median_kJ_mol` beside it, and is **version 2**. Not a silent addition: two
shapes answering to one schema name is what a version string exists to prevent. `verify_window`
reads the fingerprint and the two digests and nothing else, so a version 1 window still verifies
and is not re-run.

The count also makes the resume scoping visible — a continued window's reporter starts fresh, so
all three numbers describe only the evaluations since the resume, which was already true of the max
alone and silently.

The softcore Hamiltonian's CUDA lane carries three known failures, deliberately, decided
2026-09-19: precision on a 2.4×10⁴ kJ/mol overlap term at λ = 1. Re-run here five times on a
different card and confirmed bit-identical to the 2026-09-21 evidence — the same energy, the same
derivative and the same force, digit for digit, which is what says they are deterministic
arithmetic rather than drift. A **fourth** failure appeared in one run of five, in the file that
propagates: its Langevin integrator and barostat are unseeded, so the configuration it compares at
differs every run. That one is not evidence of anything in either direction until it is seeded.
