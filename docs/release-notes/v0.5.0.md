## What MD-tools is now

One executable, `md-openmm`, and three public commands:

```text
md-openmm build-top        a structure        -> built.xml + built.pdb + built.log
md-openmm build-md         a protocol config  -> readable run scripts
md-openmm data-register    a finished tree    -> a verified dataset under $MD_DATA
```

AIS is a `build-md` protocol, not a fourth command. There is one dataset contract (v2), one
configuration layout, and one small set of documentation.

## Configuration is browsable

The repository root held a `mode-120000` symlink, so GitHub rendered `configs` as a symlink blob.
It is now an ordinary tree, with exactly one copy of each file:

```text
configs/machine/user.config.example
configs/sys/build-top.config
configs/md/{cMD,REST2,rREST2,AIS}.config
```

They ship as **wheel data files** under `<prefix>/share/md-tools/configs/`, and
`md_tools.configs.example_root()` asks the installed distribution's own metadata where they went.
No symlink, no package-data mirror, no second hand-edited copy.

The examples are no longer generated from the schemas. The guarantee that replaced byte-equality is
stronger: **every example resolves, through the real resolver, to the model's own defaults.** An
example can be reworded freely; it cannot describe a default the code does not apply.

## AIS through `build-md`

`protocol: AIS` in the same strict resolver as cMD, REST2 and rREST2.

* **tau is the only public, persisted coordinate.** `s` and `sqrt(s)` are derived inside the
  scaler and are no longer written to the observation table — a second stored coordinate is a
  second thing that can disagree with the first.
* **Every length is an exact integer step count.** `switching_duration_ps` became
  `switching_steps` and `observation_interval_steps`; logs derive ps for the reader. Three
  divisibility rules are enforced, each refused with the arithmetic that would fix it.
* Both endpoints are included, and the schedule states that **observation 0 precedes all work**:
  it is the source configuration before any parameter change and before any propagation, so its
  cumulative work is exactly zero rather than nearly zero.
* Unchanged: the work convention `ΔW_j = U(τ_{j+1}, x_j) − U(τ_j, x_j)`, fixed volume with a
  barostat refused, independent per-path seeds, completed paths never appended to, and outputs
  validated before completion is declared.
* AIS is **not** part of the cMD stage chain. It consumes an ensemble that already exists, so
  `run.sh` takes the source as a required third argument and refuses without it.

## Contract v2

| | v1 | v2 |
|---|---|---|
| canonical path | `{namespace}/{yyyy-mm}/{dataset_name}` | `{year}/{project_name}/{data_name}` |
| shared datasets | reserved `baseline/` namespace | `{year}/common/{project}/{data}` |
| dated segment | creation **month** | completion **year**, checked against the records |
| extensions | operational record | ported, **plus a required checkpoint digest** |

v2 is a new model, not a widened v1: one model accepting both shapes is the state in which a wrong
path goes undetected. A v1 manifest fails on `schema_version`, naming the difference.

**Extensions.** Completed and archived datasets are immutable; extending one creates a new dataset
with a new id that records the parent and component; new output goes to a component the new dataset
owns, never a link into the parent; lengths are mutually consistent; status and timestamps are
ordered; a completed extension cannot finish after the dataset containing it was declared complete.

v2 additionally requires `source_checkpoint_sha256`, and `source_checkpoint_copied` for an in-place
extension — which writes into the very component it restarted from, so the run can overwrite its
own restart point. Without the copy the join stops being reproducible the moment the continuation
passes it, and nothing in the record would show that it had.

Registration validates the record, cross-checks it against `dataset.yaml`, and re-hashes the
restart checkpoint if it travelled with the data. **It never opens the parent.**

`schemas/dataset-v2.0.schema.json` and `schemas/extension-v2.0.schema.json` are generated from
their pydantic models and drift-checked by tests.

The nine builder functions `build-top` and the replica runtime actually use were extracted
**verbatim** into `openmm/builders.py` before `sysgen.py` was deleted.

**No test was removed for failing.** Each assertion was classified as migrated, obsolete with a
named deleted feature, or still blocking. Force-field provenance moved into the build record when
`forcefield.json` went; the checksum-manifest properties moved to `registry.inventory`; the AIS
switcher, omega and work-telescoping tests were rebuilt on `build-top` output; the barostat trace
now reads `in_system`/`active`/`frequency_steps` from the stage record.

Two migrations found guarantees with no new home and closed them rather than dropping the test:

* a stage did not record the `-c` parent state it consumed. It now records it **with its SHA-256**,
  and registration re-hashes recorded inputs, so a parent rewritten after a child consumed it is
  caught before it becomes false ancestry;
* nothing refused a large timestep on unrepartitioned hydrogens. It is now checked against the
  **masses serialised in the System**, which at run time is a fact rather than a request.

## One release blocker found and fixed

`.gitignore` carried a bare `build/` rule for Python artifacts. A bare pattern matches a directory
of that name at **any** depth, so it also matched `src/md_tools/build/` — the package implementing
`build-top` and `build-md`.

Those five modules had never been committed. They were absent from `origin/dev` and from the
preservation tag; a clone of this repository did not contain two of the three commands the project
exists to provide. Everything passed locally because the files were on the machine that wrote them.

Fixed by anchoring the rules (`/build/`, `/dist/`, `/data/`, `/logs/`) and committing the modules.
A test in `test_suite_integrity.py` now walks `src/`, `tests/` and `configs/` and fails if
`git check-ignore` matches any source file. Verified by cloning `dev` and building a working wheel
from the clone.

## CI

`.github/workflows/release.yml` was not evidence for this package: it invoked `show-default`,
`sys-config`, `sys-gen` and `md-gen`, none of which exist. It is replaced by
`.github/workflows/ci.yml`, which runs on pull requests, on pushes to `dev` and `main`, and on
manual dispatch — so it speaks for the branch under review rather than only for a tag. Tag-driven
validation moves to `v*`; `openmm-v*` named this package under its former name.

The job builds the wheel, installs it with no source tree importable, and then runs every
interface check from a directory outside the checkout — proven, not assumed, by asserting
`md_tools` resolves inside `site-packages`. It validates the three commands, refuses the retired
ones, locates and resolves the shipped examples through distribution metadata, generates every
protocol and compiles what is written, compares both exported schemas against their models, and
runs the non-GPU lane with a skip treated as a failure.

It runs **no dynamics** and says so in a job notice. There is no CUDA runner; the GPU lane is
local and is the table below. Its status has not been observed on GitHub yet — this branch has not
been pushed to a pull request — so every check above is reported from the local rehearsal of the
same steps, not from a green tick.

## Remaining

Recorded rather than hidden.

**A registration message, in one narrow window.** Interrupted between the source directory being
removed and the symlink being created, a re-run reports `-idata ...: does not exist` instead of
saying the dataset is already registered. At that point the commit has happened, so the data is at
its final path, complete and verifiable — the test proves exactly that. This costs a confusing
message, never data.

**The instruction's own file count.** It asks for "all seven" configuration examples while the
tree it draws enumerates six. The tree is the specification and six is what ships; the test asserts
the exact set rather than any count, so it fails both on a missing file and on an undeclared one.

**The ladder's default process model.** Run without `mpiexec`, rREST2 is a single process holding
every state and letting OpenMM choose the device. This is correct and is what the smoke test
exercises; the per-rank placement policy (`select_device_for_rank`) is asserted separately, but a
multi-process ladder on this machine is not part of the automated lane.

**Not done here, by instruction.** `dev` is not merged to `main`, nothing is published to PyPI,
no `v0.5.0` tag exists, and the version remains `0.5.0.dev0`. This is a release candidate for
review, not a release.
